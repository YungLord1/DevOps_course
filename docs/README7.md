## 1. Создание инфраструктуры 

Первым делом была подготовлена среда внутри кластера:

*   **Namespace (`myapp`)**: Создано изолированное пространство имен для предотвращения конфликтов с другими сервисами.

*   **Service (ClusterIP)**: Создана внутренняя точка доступа для подов, обеспечивающая стабильный IP внутри кластера.

## 2. Выбор стека: MetalLB + Traefik

Для обеспечения доступа к приложению извне была выбрана связка **MetalLB** и **Traefik**.

### Почему MetalLB?
В облачных решениях (AWS, GCP) внешний IP выдается автоматически. В локальном кластере (Bare Metal) Kubernetes этого делать не умеет. 
*   **Функция**: MetalLB выделяет «настоящий» внешний IP из пула адресов вашей локальной сети. Без него сервис типа `LoadBalancer` навсегда остался бы в статусе `<pending>`.

### Почему Traefik?
Traefik выступает в роли **Ingress-контроллера**.
*   **L7-маршрутизация**: Позволяет использовать одно внешнее соединение (IP) для доступа к множеству сервисов по доменным именам (например, `chach.industry.com`).
*   **Автоматизация**: Он динамически отслеживает изменения в кластере и сам настраивает правила проксирования.
*   **HTTPS**: Имеет удобную поддержку TLS.

## 3. Решение проблем с DNS

После запуска возникла проблема: приложение отвечало `data: {}`, так как не могло получить данные от внешнего API.

*  Тесты внутри подов показали ошибку `URLError: <urlopen error [Errno -5] Name has no usable address>`.
*  В манифест Deployment были внесены изменения:
    *   `dnsPolicy: "None"` — игнорирование настроек кластера.
    *   `dnsConfig` — принудительно указать публичные DNS серверы (Google: `8.8.8.8`, `1.1.1.1`).
*   **Результат**: Приложение получило доступ к интернету и начало отдавать курсы валют.

## 4. Настройка защищенного соединения (HTTPS)

Для защиты данных был внедрен протокол HTTPS на базе самоподписанного сертификата.

### Шаги реализации:
1.  **Генерация ключей**: С помощью OpenSSL созданы приватный ключ (`tls.key`) и сертификат (`tls.crt`) для домена `chach.industry.com`.
2.  **Kubernetes Secret**: Ключи загружены в кластер командой:
    ```bash
    kubectl create secret tls chach-tls-secret --cert=tls.crt --key=tls.key -n myapp
    ```
3.  **Обновление Ingress**: Создан финальный манифест, объединяющий HTTP и HTTPS доступ
