### 2. Роль kube

```markdown

## Подробное описание
Эта роль является ядром для установки базовых утилит Kubernetes на ноды (мастера и воркеры). Она устанавливает прокси(признаюсь захардкодил в глупую, очень долго возился с прокси, в следующй раз буду скачивать пакеты в локальный репозиторий), прокидывает GPG ключи, добавляет официальные репозитории и скачивает бинарники.

---

## Логика работы
Архитектура роли разбита на 3 этапа (в `tasks/main.yml` прописан Include каждого этапа):

### prepare.yml
1. Создает файл `/etc/apt/apt.conf.d/99proxy` для прямого указания прокси пакетному менеджеру APT
2. Обновляет кэш.
3. Ставит утилиты для работы с репозиториями: `ca-certificates`, `curl`, `gnupg`, `apt-transport-https`.

### repository.yml`
1. Забирает GPG ключ с `pkgs.k8s.io` и кладет его в директорию `/etc/apt/keyrings/`.
2. Создает файл репо `kubernetes.list`, привязывая его строго к скачанному GPG-ключу.

### install.yml
1. Устанавливает пакеты K8s: `kubelet`, `kubeadm`, `kubectl`.
2.Выполняет `dpkg_selections: hold` для этих пакетов. Т.Е. они не будут обновляться системными утилитами. Продолжение в следующей домашке...
3. Включает демон `kubelet` в автозагрузку и запускает его.

---

## Переменные

Лежат в `defaults/main.yml`.

| Переменная | Тип | По умолчанию | Описание |
|---|---|---|---|
| `k8s_version` | String | `"1.32"` | Мажорная/Минорная версия компонентов Kubernetes. Обязательно должна совпадать с версией CRI-O. |
| `k8s_base_packages` | List | `[ca-certificates, curl, gnupg, lsb-release, apt-transport-https]` | Системные утилиты, необходимые для установки защищенных репозиториев. |
| `k8s_packages` | List | `[kubelet, kubeadm, kubectl]` | Основные пакеты кластера. |
| `k8s_keyring_file` | Path | `"/etc/apt/keyrings/kubernetes-apt-keyring.asc"` | Место сохранения ключа подписи репозитория. |
| `k8s_repo_definition` | String | `"deb [signed-by={{...}}] ..."` | Строка конфигурации репозитория для файла `sources.list.d`. |
| `kube_my_variable` | String | `"default_value"` | Тестовая переменная (шаблон для нейминга кастомных vars). |

## Handlers (Обработчики)
* **`Restart kubelet`** — выполняет рестарт демона Kubelet с флагом `daemon_reload: true`. Вызывается, если меняются конфигурационные файлы, отвечающие за старт узла.

## Тестирование (Molecule)
Тестирование роли реализовано в папке `molecule/default`.

**Особенности тестов:**
На этапе подготовки (`prepare.yml`) Molecule просто проверяет связность системы. Работа с прокси внутри тестовых Docker-контейнеров закомментирована, так как тестовая среда обычно имеет прямой выход в интернет, в отличие от продуктовых нод.

**Проверки Testinfra (`test_default.py`):**
1. Проверка системных файлов (владельцы `/etc/hosts`).
2. Цикл `for pkg in ["kubelet", "kubeadm", "kubectl"]` проверяет успешную установку каждого бинарника.
3. Проверка службы `kubelet` (убеждаемся, что она находится в статусе `enabled`, готовая к запуску кластера).
